## Adjudicated Findings (`RT-01` .. `RT-09`)

1. **RT-01 (Critical — Accept):** iOS `onSwitchToSecondaryWifi` (`MainViewModel.swift:683-749`) immediately returns stale `Band A` IP (`snap.isOnOntSubnet == true`) on `attemptIdx == 1` (`0ms`) and every `3.0s` (`waitedForegroundTicks >= 12`), making the `6s -> 12s -> 18s` `tryJoinWifiDetailed` retry unreachable while causing Sideloadly builds to lock the ONT admin session on `Band A` for `15s` + sleep `5s..20s` blindly; furthermore, `NEHotspotConfigurationError.internal` (`code == 8`) is returned on both unsigned Sideloadly `.ipa` (`< 40ms`) and entitled transient failures (`>= 40ms`), `alreadyAssociated` (`code == 13`) is treated as failure, and Open profiles (`"open"`) leak if DHCP fails after `apply`.
   - *Applied fix (`plan.md`, `phase-03`, `phase-04`):* In `IosWifiMonitor.tryJoinWifiDetailed`, treat `error == nil` or `alreadyAssociated` (`code == 13`) as L2-joined (recording `joinedOpenSsidBox` immediately *before* `awaitWifiIpv4Ready(maxWaitMs: 15_000)`), and classify `code == 8` with elapsed duration `< 40ms` as `.entitlementUnavailable` vs `>= 40ms` as `.transientFailure`. In `MainViewModel.swift`, run `6s -> 12s -> 18s` auto-join retries directly inside `onSwitchToSecondaryWifi` on `.transientFailure`; on `.entitlementUnavailable` (manual Sideloadly flow), show `HandoverPromptState` (populating `UIPasteboard` only here) and wait for `ipChanged || wakeChanged` (or `>= 15s` foreground return grace) — never returning `Band A`'s unchanged IP at `0ms`. In `OntMobileDriver.swift`, throw `StillOnPrimaryBandError` after **2 consecutive wrong-band reads** (`~2s`), immediately `logout()`, and use a short `1.5s` sleep on `StillOnPrimaryBandError` (reserving `5s -> 10s -> 15s -> 20s` backoff for real `OntNetworkError` link drops).

2. **RT-02 (Critical — Accept):** Android `OntWifiConnector.switchToConfiguredSecondaryWifi` (`OntWifiConnector.kt:421, 432, 441, 477-495, 573-594`) resets `handoverStartMicros` and re-runs `initialSettleMs (8s) + Phase A (45s)` on every outer Step 7 retry even when `4 / 120s` scan quota was pre-exhausted in `OntWifiScannerDialog` (`MainViewModel.kt:605`); re-checking `scanResults` after `8s` without a newer scan reads the exact same cached beacon; `val prevNetwork = excludedNetwork ?: boundWifiNetwork` (`:421`) overwrites explicit `excludedNetwork = null` on 2.4GHz-only re-runs (`MainViewModel.kt:900-908`); and same-SSID dual-band (`ssid24g == ssid5g`) loops on `wl0` without BSSID locking.
   - *Applied fix (`plan.md`, `phase-01`, `phase-02`, `phase-04`):* Capture `step6CompletedMicros` **once** before the outer Step 7 loop and pass `minScanTimestampMicros` + `outerAttemptIndex` into `switchToConfiguredSecondaryWifi` (`outerAttemptIndex == 1`: `initialSettleMs = 8_000L`, `postBeaconReadyDelayMs = 8_000L`; `outerAttemptIndex >= 2`: `initialSettleMs = 0L`, `postBeaconReadyDelayMs = 2_000L`). If `hasAvailableProcessScanQuota() == false` and no passive `SCAN_RESULTS_AVAILABLE_ACTION` arrives within `8_000L`, exit Phase A early into Phase B (`WifiNetworkSpecifier` triggers Android's quota-exempt system scan); only treat `scanResults` as proof of radio drop during `postBeaconReadyDelayMs` if a newer scan broadcast arrived (`sr.timestamp > firstSeenMicros`) with `targetSsid` absent. Fix `:421` to `val prevNetwork = excludedNetwork`, enforce `dhcpWaitTimeoutMs` + `linkStabilityMs` on `findAlreadyConnectedTargetNetwork`, and apply `specBuilder.setBssid(...)` from `targetBssidHint` when retrying after `StillOnPrimaryBandException`.

3. **RT-03 (Critical — Accept):** URL-encoded passwords (`Passwd2@` -> `Passwd2%40`) bypass raw `activeRunSecrets`, `OntInputValidator.kt:32-46` lacks JSON-quoted/space-aware regex parity with `OntInputValidator.swift:385-428`, registering `adminDefaultPass = "admin"` (`length >= 4`) corrupts `user=admin` and UI messages, omitting `effectiveWifi24Pass`/`effectiveWifi5Pass`/`lastKnownAdminPass`/scanner `passphrase` leaks real passwords, and async scrubbing or clearing `activeRunSecrets` before `MainViewModel` `catch` logs exposes raw credentials on failure (`MainViewModel.kt:1001-1035`).
   - *Applied fix (`plan.md`, `phase-01`, `phase-02`, `phase-03`, `phase-04`):* Unify `OntInputValidator.kt` and `OntInputValidator.swift` so all sensitive keys (`pppPassword`, `pass`, `newPass`, `oldPass`, `wl_wpa_psk`, `nvramWlWpaPsk`, `nvramWlRadiusKey`, `nvramWlKey[1-4]?`, `password`, `passphrase`, `wpa_psk`, `preSharedKey`, `sessionKey`, `data`) mask URL-form, JSON-quoted (including spaces), and `key: value` formats. Scrub synchronously on the caller thread inside `AppDiagnosticLogger.log(...)` *before* RAM/disk insertion; register raw + `urlEncodeFormValue` + `ontEncodeQuery` variants for `adminNewPass`, `adminDefaultPass`, `lastKnownAdminPass`, `passPppoe`, `effectiveWifi24Pass`, `effectiveWifi5Pass`, `defaultWifi5Pass`, and scanner `passphrase` while excluding reserved tokens (`"admin"`, `"root"`, `"open"`, `"null"`, `"true"`, `"false"`, `"192.168.1.1"`) and requiring `length >= 6` for unkeyed literal replacement; clear `activeRunSecrets` only *after* `MainViewModel`'s error logging finishes; and mask middle chars of `accountPppoe`, `SLID`, and MAC/BSSID (`AA:BB:CC:**:**:D8`) in exported `.txt` logs.
